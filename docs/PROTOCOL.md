# 实验协议与交付标准

## 研究问题与待验证假设

安全 SFT / DPO 对未见攻击的改善是否不同？改善是否伴随正常任务损失或过度拒答？
这是一组待检验假设，没有预先承诺正向结论或新方法。

| 假设 | 最小证据 | 不能推出 |
| --- | --- | --- |
| 额外安全训练改变安全行为 | 原模型 / SFT / DPO，固定评测 | 所有安全风险下降 |
| 改善具有一定泛化 | 持出攻击家族或攻击方法 | 对任意未来攻击有效 |
| 正常数据混合影响取舍 | 一项混合消融，安全与正常表现同时报告 | 证明某个单一内部机制 |
| 现象能在另一规模复现 | 32B 原模型与预选方案 | 普遍的 scaling law |

## 模型与训练对照

- 主模型 Qwen3-8B，非思考模式；模型 commit 固定。
- 原模型作为无额外微调基线；SFT 和 DPO 分别从它初始化。
- SFT 用相同 prompt 的 chosen；DPO 用 chosen/rejected，参考策略固定。
- BF16 LoRA，初始建议 rank 16、alpha 32、dropout 0.05；这是待验证起点，不是最佳参数。
- 先测序列长度 512 和少量 step；正式起点 2048、每卡 batch 1，再按测量调整。
- GPU 时间、有效回答 Token、峰值显存、训练步数分列。相同 epoch 不代表相同计算预算。
- 32B 的方案由开发集选定，不能根据最终测试结果选择。

## 数据

公开偏好数据候选：[PKU-SafeRLHF](https://huggingface.co/datasets/PKU-Alignment/PKU-SafeRLHF)。
首次人工审查后选择约 2,000–5,000 对，固定 dataset revision 和筛选统计。安全与 helpfulness 标签分开处理；排除 chosen 不安全或标签歧义的样本，并记录规则。

train / dev / test 按问题家族或来源划分。完全重复、标准化重复、近似模板分别检查。数据集划分前，先确定研究所需的持出条件。仅 hash 去重不能证明语义无泄漏。

## 评测集合

- [HarmBench](https://arxiv.org/abs/2402.04249)：明确使用的行为集合、攻击方法和官方判分规则；子集必须公开 ID 与筛选原则。
- [XSTest](https://github.com/paul-rottger/xstest)：正常请求的过度拒答。
- [IFEval](https://arxiv.org/abs/2311.07911)：正常指令遵循，限定为这个维度。
- 可选 [AgentDojo](https://github.com/ethz-spylab/agentdojo)：仅在主线完成后探索；模拟工具、干净基线和受攻击表现分表。

预算起点：先各取 10–20 条做评分与格式调试，再冻结正式子集。正式样本量依据基准大小和预算确定，记录实际数目，不凭小样本宣称显著差异。

## 指标与记录

每条记录至少包含 sample_id、family、split、run_id、attack_id、attempt_index、output、judgment、judge_version、error、latency、tokens。
原始记录存服务器。GitHub 上可只放 schema、统计和经检查的案例。

1. ASR：明确是每次尝试还是每目标预算内至少一次成功；固定预算。
2. 正常任务成功率与过度拒答率分列。
3. 超时、解析失败、工具错误、无效攻击单列，分母规则固定。
4. 比例附样本量与区间；成对比较按问题或家族抽样。
5. 至少对关键方案做独立训练种子复核；若预算不足，明确单种子局限。
6. 裁判抽样人工复核，覆盖成功/失败/异常及风险类别。
7. 模型、数据、模板、评分器、脚本 commit 一并记录。

不得用简单字符串拒答检测代替官方安全评分，也不得用一个模型生成偏好、打训练分和做最终评价而不检查共享偏差。

## 交付

README 首页一个问题、一张主图、个人贡献和复现入口；4–6 页报告；8–10 页 slides；3–5 个有原始输出与评分依据的失败案例。
配置模板、教学数字、冒烟输出、真实训练结果分开标记。结果未知时写 `TBD`。

API 可用于独立评分或外部动作防护测试；不能据此声称本地 LoRA / DPO 已在闭源模型上验证。
